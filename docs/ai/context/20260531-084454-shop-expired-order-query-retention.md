# 手机号查询保留过期订单

## 背景

用户要求：即使 API key 已经过期，手机号查询页面也要持久化保留并展示这些查询记录。

## 当前设计

- `orders` 是订单历史表，不因 API key 过期而删除。
- `/api/orders?phone=...` 按手机号查询该手机号下的全部订单，不按 `expires_at` 过滤。
- 订单状态由 `expires_at` 动态计算：
  - 未过期：`active` / 使用中
  - 已过期：`expired` / 已失效

## 本次补强

- 查询页文案明确说明：过期订单会显示为“已失效”，但仍会保留在查询结果里。
- 测试增加过期订单场景，确保过期订单仍返回完整 API key 和 `expired` 状态。

## Tradeoff

- 订单历史保留在 SQLite 中，便于用户用手机号长期查询。
- API key 是否真的可用由 `expires_at` 表示，不通过删除订单来表达失效。
