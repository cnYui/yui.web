# 支付宝与微信支付集成计划

## 背景

当前 Shop 模块是静态演示页面，订单和支付状态保存在浏览器 `localStorage`。用户希望进一步打通支付宝和微信支付接口。

## 必须解决的问题

- 私钥、商户证书、支付回调验签都必须在服务端完成，不能放到前端。
- 前端支付页需要通过后端创建订单和支付单。
- 支付成功不能相信前端按钮或跳转，必须以支付平台回调和服务端订单状态为准。
- 当前项目没有数据库，先使用内存订单仓库完成本地集成结构；生产环境必须替换为数据库。

## 技术方案

- 新增 `server.js`，同时提供静态文件服务和支付 API。
- 新增 `.env.example`，列出支付宝、微信支付所需配置。
- 新增后端接口：
  - `POST /api/orders`：创建订单。
  - `GET /api/orders/:id`：查询订单。
  - `POST /api/pay/alipay`：创建支付宝支付表单。
  - `POST /api/pay/wechat`：创建微信 Native 支付二维码内容。
  - `POST /api/pay/alipay/notify`：支付宝异步通知回调。
  - `POST /api/pay/wechat/notify`：微信支付通知回调占位。
- 前端 `/shop/pay/` 改为调用后端接口展示真实支付入口。

## 关键取舍

- 支付宝使用 `alipay-sdk`，因为它是支付宝开放平台 Node.js SDK。
- 微信支付先用 Node 内置 `crypto` 和 `fetch` 按 V3 签名请求，不额外引入非官方 SDK。
- 本地无商户配置时，接口返回 `PAYMENT_NOT_CONFIGURED`，前端显示配置提示并保留演示成功按钮。
