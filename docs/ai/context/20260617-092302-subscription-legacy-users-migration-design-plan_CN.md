# 订阅池老用户迁移设计

## 背景

订阅池分支上线后，API key 放行条件变为“账号有有效订阅，并且每日套餐额度或加量包余额可用”。线上旧库还没有 `account_subscriptions` 等订阅池表，旧系统中的人民币余额和旧人民币扣费流水不能直接作为新美元订阅池余额使用。

用户已明确确认 10 个老用户需要直接迁移为 29 元套餐：

- `15776812883`
- `17371571728`
- `19814722044`
- `13813756694`
- `18014503779`
- `15062376174`
- `15995436627`
- `18367290091`
- `13052071067`
- `13584052801`

## 迁移决策

- 上述 10 个手机号从 2026-06-17 开始获得 29 元档套餐，每天 19 美元额度。
- 会员有效期从 `2026-06-17T00:00:00+08:00` 到 `2026-07-17T00:00:00+08:00`。
- 旧金额不迁入新美元扣费账本，不创建旧美元扣费记录。
- 旧 usage 只保留 token 统计；新 `api_usd_charge_records` 从切换后新 usage 开始产生。
- 其他用户不创建有效套餐，上线后展示为无套餐状态。
- 如果数据库里已经存在非白名单用户的 active 订阅，迁移脚本在 apply 时必须把它们置为 `cancelled`，保证“其他用户无套餐”不是依赖初始状态的假设。
- 迁移必须能 dry-run，apply 前必须备份数据库。

## 实现计划

1. 新增 `scripts/shop-migrate-subscription-legacy-users.js`。
2. 新增测试覆盖 dry-run 不写库、apply 只迁移白名单、重复 apply 幂等、非白名单保持无套餐。
3. 脚本使用 `openShopDatabase(dbPath)` 确保新表和默认套餐存在。
4. 迁移时为每个白名单手机号插入一条 `subscription_orders` 的 approved 迁移订单，以及一条 `account_subscriptions` active 订阅。
5. 如果手机号没有用户记录，脚本不自动造用户，报告到 `missingUsers`。
6. 如果手机号没有兑换订单或托管 API key，脚本仍报告，但不阻断迁移；因为用户已人工确认名单，脚本只负责把会员状态迁进去。
7. 对已有 active 订阅的白名单用户跳过创建，保证幂等。
8. 对非白名单 active 订阅执行取消，避免测试或旧数据残留导致其他用户上线后仍有套餐。
9. 使用独立 id 前缀 `LEGACY-SUB-` 和 `MIGSUB-`，避免和用户正常购买订单混淆。

## 验收

- dry-run 输出会列出 10 个手机号的计划，不写任何订阅或订单。
- apply 后只有这 10 个手机号有 active 订阅。
- 订阅计划均为 `sub_29_daily_19_usd`。
- `started_at` / `expires_at` 固定为上述东八区时间。
- 旧人民币余额、旧扣费记录和旧 usage 不被修改。
