# 首页线索墙：去掉肖像卡，便签可拖动，红线由访客自己连

## 背景

- 墙上的肖像卡（拍立得 + 「悠一 Yui」）点开后进的就是 `#about`，和旁边「关于我」纸条是同一份档案，墙上有两个入口指向同一处。要求：肖像卡从墙上下架，只留「关于我」。
- 原来的红线是写死的 10 根，把图钉连成一张固定的网，访客只能看。要求：去掉这些线；点两枚不同的图钉时才拉一根红线；墙上的照片和便签能按住拖到别处重新布局，点一下仍然是打开；拖动时图钉跟着走。

## 做了什么

### 去掉肖像卡

- `index.html` 删掉 `.cw-card--portrait`；`js/clue-wall.js` 删掉 `COVERS.aboutPortrait`；`js/clue-i18n.js` 删掉 `wall.portrait.caption` / `.aria` / `.alt`；样式里的 `.cw-card--portrait`、`.cw-portrait-*`、悬停和 `:lang(en)` 规则一并删掉。
- 肖像照片本身还在「关于我」档案里（`.cw-about-photo`），只是不再单独占墙上一张卡。墙上点得开的便签从 7 张变 6 张（每份档案一张）。
- 肖像走后正中间空了一块：「关于我」挪到中间，博客上移到左上，联系卡跟着上移，拍立得挪到左下补位。默认坐标在 `styles/clue-wall.css`（`.cw-card--about` 575/175、`.cw-card--blog` 100/120、`.cw-bizcard` 150/392、`.cw-polaroid` 130/560）。

### 新增 `js/clue-board.js`：图钉、红线、拖动

- 墙上每张纸（6 张便签 + 联系卡 + 拍立得 + GitHub 贡献图）在 `index.html` 里用 `data-pins` 声明图钉：`red` / `blue` / `gold`，可选 `:左,上`，左为负数时从右边量起，不写位置就钉在上边正中间 18px 处；`data-tilt` 是纸的倾角（必须和样式里的 `rotate()` 一致，测试会核对）。「关于我」是金色图钉，旅行地图和贡献图保持原来的两枚蓝色图钉，其余一枚红色。联系卡原来没有图钉，这次补了一枚。
- 图钉不再是写死的 `<span>`，由脚本按纸的位置、尺寸和倾角算出来，放在 `#cwPins` 里；红线画在 `.cw-strings` 的 `<g>` 里。两层的 z-index 是 900 / 901，高于所有纸（纸被拖起时 z-index 从 11 递增，上限 800，到顶后按现有顺序重新编号）。
- **点两枚不同的图钉连线**：第一下选中（放大、亮一圈、从它拉一根虚线跟着光标），第二下连上；再点同一对剪断；点同一枚图钉、点空白处、按 Esc 都取消选中。线是自然下垂的曲线，最多垂 46px。
- **拖动**：按住纸（或它的图钉）挪动超过 6 屏幕像素算拖动，之内都算点击；拖动期间纸抬起、阴影加深、光标变抓手，镜头的缓慢漂移暂停；纸被限制在软木板内。拖完那一下补发的 `click` 在捕获阶段拦掉，不会误开便签。联系卡、拍立得、贡献图只能拖和连线，不是便签，点不开。
- 贡献图要等数据到达才可见：数据到达之前 `pointer-events: none`，它的两枚图钉由 `data-pin-ready="is-ready"` 管着，同步隐藏。
- 打开档案时 `#cwScene` 是 `inert`，脚本不处理任何指针事件；便签「钉回墙上」用的是现量的 `getBoundingClientRect()`，所以会回到拖动之后的新位置。

### 屏幕坐标怎么换算回软木板

- 墙面被 3D 镜头拍着（`rotateX/Y` + 透视），屏幕位移不能直接当软木板位移。软木板四个角各放一个 2×2 的隐形探针（`.cw-probe`），用它们在屏幕上的位置解一个单应矩阵（8 元线性方程组，`solveHomography`），把指针换算回 1700 × 880 的软木板坐标。
- 每帧现解：镜头在转、在漂、窗口在变都不影响。实测 11 枚图钉反算回自己的 `left/top`，最大误差 0.04 个设计像素；拖完之后图钉正好落在松手的指针位置。

### 其它

- 提示语 `ui.hint` 三语都补了「拖动便签换位置 · 点两枚图钉连线」。
- `?v=` 统一提到 `20261014-3`（`clue-wall.css`、`clue-i18n.js`、`clue-wall.js`，新增的 `clue-board.js`）；`clue-data.js` 和 `github-contributions.js` 没改，保持原来的号。
- 刻意没做：不持久化（刷新后回到默认布局、红线清空）；不支持键盘拖动和连线（便签本身仍可用键盘聚焦和 Enter 打开，图钉层是 `aria-hidden` 的纯指针玩法）。

## 测试

- 新增 `test/home-clue-board.test.js`：肖像卡无残留、页面里不再有写死的图钉和红线、`clue-board.js` 在 `clue-wall.js` 之后加载、每张纸的 `data-tilt` 和样式 `rotate()` 一致、`data-pins` 解析、图钉随位置和倾角平移 / 旋转、红线路径、单应矩阵在透视下精确还原（含退化返回 `null`）。
- 更新 `test/home-clue-wall.test.js`、`test/home-i18n.test.js`（便签 7 → 6、封面 7 → 6）和 `test/github-contributions-card.test.js`（数据到达之后才接收指针）。
- `npm test` 151 个里 150 通过。唯一失败的是「Resume 页面所有 data-i18n key 都有中英日翻译」（`js/lang.js` 里找不到 `// Anime page specific` 标记），纯净的 `origin/main` 上同样失败（143 个里 1 个），与本次改动无关。
- 浏览器里实测（900×560 和手机宽度）：拖便签、拖图钉、拖到边缘被夹住、点图钉选中 + 虚线、连线、再点剪断、拖动时红线端点跟着走、单击仍打开档案并回到新位置、贡献图图钉随数据到达显隐。触屏手势没有真机验证。
