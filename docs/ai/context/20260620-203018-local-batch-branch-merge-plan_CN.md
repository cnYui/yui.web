# 本地未提交修改分批提交与合并计划

## 背景

- 当前工作区存在 6 个修改文件和 109 个删除文件。
- 当前分支为 `codex/sub2api-shop-entry`，其远端跟踪分支已不存在。
- 本地 `main` 与 `origin/main` 已分叉，本次按用户要求合并到本地 `main`，不擅自重置或覆盖本地主分支历史。

## 必须解决的问题

- 将本地未提交修改按主题拆分到多个新分支。
- 每个新分支提交前后审查 diff，避免把无关修改混入同一提交。
- 每轮验证与 review 后合并回本地 `main`。
- 保留当前大量历史上下文删除的风险边界，避免和功能行为变更混在同一批。

## 分批方案

1. `codex/batch-shop-sub2api-20260620`
   - 范围：当前分支已有的 Shop 到 Sub2API 基线提交，以及未提交的 Shop 首页极简入口、旧发 Key 退役测试和相关服务端默认值调整。
   - 目的：避免把测试失败的基线中间态合并进 `main`，一次性完成可验证的功能状态。

2. `codex/batch-agents-memory-20260620`
   - 范围：`AGENTS.md` 与本次计划文档。
   - 目的：保存协作记忆与本次分批操作计划。

3. `codex/batch-context-archive-cleanup-20260620`
   - 范围：`docs/ai/context/` 下已删除的历史上下文文档和截图。
   - 目的：将历史上下文清理作为单独批次，便于独立 review 和回滚。

## 执行中调整

- 预备 review 发现仅合并当前分支已有基线会让 `npm test` 失败：198 个测试中 152 个通过、46 个失败，失败集中在旧发 Key 写路径已退役但测试仍断言成功。
- 因此第一批改为“基线 + 旧发 Key 测试改造 + Shop 极简入口”整体提交，并以全量测试通过作为合并门禁。

## Review 重点

- 每轮只检查当前分支相对本地 `main` 的 diff。
- 功能批次至少运行相关测试或 `git diff --check`。
- 文档清理批次重点确认删除范围全部限定在 `docs/ai/context/`。
- 若某批出现冲突或测试失败，先修复或停止报告，不继续合并。
