# 加量包必须依附有效套餐

## 背景

用户在 Account 页面发现：账号未开通套餐时仍可以提交加量包订单。这个流程不符合订阅池设计，因为加量包是套餐额度用完后的备用额度，不是独立按量余额。

## 设计

- 后端作为硬约束：`POST /api/account/addon-orders` 必须检测当前登录手机号存在有效套餐，才允许创建加量包订单。
- 前端作为即时提示：无有效套餐时禁用“提交加量包订单”，并显示“请先开通套餐，再购买加量包。”。
- 已有加量包余额仍保持长期保留；这里只限制“新提交加量包订单”，不清理历史余额。
- 判断有效套餐沿用订阅池状态中的 `subscription`，即后端 `started_at <= now < expires_at` 的 active subscription。

## 验收

- 无套餐用户提交加量包订单返回 409，错误码 `SUBSCRIPTION_REQUIRED_FOR_ADDON`。
- Account 页面无套餐时可看到明确提示，提交按钮不可用。
- 已有套餐用户仍可正常提交加量包订单。
