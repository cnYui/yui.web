# 发布 PR 与合并上下文

## 背景

本次任务不是新增实现，而是把当前工作区已有修改从 `main` 切到新分支，提交、推送到 GitHub，创建指向 `main` 的 PR，完成客观 review 后合并，并同步本地与远端代码。

## 分支策略

- 当前本地 `main` 比 `origin/main` 领先 1 个提交，并包含未提交工作区修改。
- 已从当前状态创建分支 `codex/publish-current-project-changes`，保证本地提交与未提交修改都留在发布分支上处理。

## 提交范围决策

- `superpowers/` 是完整外部项目副本，包含嵌套 `.git` 目录，不属于站点代码、内容或运行时依赖。
- 为避免把外部仓库误提交进当前项目，本次提交排除 `superpowers/`，并将其加入 `.gitignore`。
- `.env` 继续保持忽略，只提交 `.env.example` 作为本地配置模板。

## 验证与合并约束

- 提交前需要运行项目现有验证：`npm test` 与必要的 CSS 构建。
- PR 目标分支必须是 `main`。
- 合并前需要检查 PR diff、CI 状态和安全边界，未通过验证不合并。
