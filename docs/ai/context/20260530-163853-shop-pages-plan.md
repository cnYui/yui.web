# Shop 购买模块页面设计计划

## 背景

当前项目是静态个人官网，已有页面采用目录路由，例如 `/blog/`、`/projects/`、`/travel/`。本次需要在官网根路径下新增购买模块，并在本机主页顶部导航加入 Shop 入口。

## 必须解决的问题

- 给访问者一个清晰的购买入口。
- 购买时收集手机号，用于后续结果查询。
- 页面流程覆盖支付宝与微信支付入口。
- 支付成功后展示相应内容。
- 当前阶段先完成静态页面与本地展示，不实现真实支付后端。

## 路由设计

- `/shop/`：购买主页，展示商品、价格、购买入口和流程。
- `/shop/order/`：下单页，填写手机号并生成本地演示订单。
- `/shop/pay/`：支付页，选择支付宝或微信支付，展示支付二维码占位和支付状态说明。
- `/shop/result/`：支付结果页，展示支付成功、处理中或失败状态。
- `/shop/query/`：手机号查询页，输入手机号查询本地演示订单。
- `/shop/content/`：内容页，支付成功后展示购买内容或交付结果。

## 关键取舍

- 当前项目没有后端，支付宝和微信真实支付不能只靠静态 HTML 完成。本次只做前端流程壳和演示状态。
- 真实上线时必须增加后端：创建订单、支付预下单、支付回调验签、订单查询、内容授权。
- 前端不能以跳转或按钮点击作为支付成功依据，必须以后端回调确认的订单状态为准。
- 为保持个人官网一致性，页面继续使用白底、细边框、Playfair Display + Inter、Material Symbols 图标和现有深色模式。

## 实现计划

1. 新增 `shop/` 目录和 5 个子目录，每个目录提供 `index.html`。
2. 新增 `shop/shop.js`，封装本地演示订单状态、手机号校验和页面间数据传递。
3. 更新首页顶部导航和移动端菜单，加入 `/shop/`。
4. 更新 `tailwind.config.js`，让 Tailwind 扫描 `shop/**/*.html` 和 `shop/**/*.js`。
5. 运行 CSS 构建，启动本地静态服务并用浏览器检查页面可访问性。
