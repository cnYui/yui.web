# Shop 首页按量计费文案与按钮布局计划

## 目标

将 `/shop/` 首页从“Codex 每月额度兑换”的旧口径改为“Codex 按量计费”的新口径，并修复首屏 4 个按钮在桌面宽度下被硬换行的问题。

## 设计

首页首屏保持现有作品集风格和左右双栏结构，不引入新的交互逻辑，只调整文案与布局：

- 左侧标签改为 `Codex usage billing`。
- 标题改为 `Codex 按量计费`。
- 说明文案改为：私下开通后发放邀请码，用户用手机号和邀请码兑换 API key；请求用量按 token 记录；登录后可以查看自己的用量和账单。
- 按钮改为稳定的两列网格，固定高度并让文字居中，避免“手机号查/询”“使用方/法”这类生硬断行。
- 按钮文案改为：
  - `兑换 API key`
  - `手机号查询`
  - `使用方法`
  - `登录账户`
- 右侧说明卡改为：
  - `私下开通`
  - `兑换 API key`
  - `按量记录`

## 实现计划

1. 在 `test/shop-flow.test.js` 增加或调整静态 HTML 测试：
   - 首页必须包含 `Codex 按量计费`、`按实际 token 记录`、`登录账户`。
   - 首页不得再包含 `每月 30 元人民币`、`31 天有效`、`额度兑换`。
   - 首页按钮容器必须使用网格布局，包含四个主按钮。
2. 运行目标测试，确认旧首页导致测试失败。
3. 修改 `shop/index.html`：
   - 更新左侧标签、标题、说明文案。
   - 将按钮容器从 `flex` 改为 `grid grid-cols-2`，按钮增加固定高度、居中、`whitespace-nowrap`。
   - 更新右侧三张说明卡文字。
4. 如果新增 Tailwind class 导致 `styles/site.css` 需要更新，运行 `npm run build:css`。
5. 运行 `npm test` 和 `npm run build:css`。
6. 使用本地 HTTP 或静态检查确认首页不再出现旧月费文案，按钮文字保持完整。

## 取舍

- 不修改兑换、登录、查询等业务逻辑，避免把文案调整扩大成计费系统改造。
- 首页只说明“按 token 记录用量”，不在首屏承诺具体单价；价格口径后续应由账单/价格表功能统一维护。
- 保留邀请码兑换入口，因为当前 API key 发放流程仍依赖邀请码。
